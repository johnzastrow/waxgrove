Waxgrove — connect wizard (F13) & job surface (F22)

The two hard
surfaces

Neither is glamorous, and both are where a self-hosted app usually loses people. They are hard for opposite reasons.

Connect — the leaving problem

BYO-first (D6) means the user must go to developer.spotify.com, create an app, and come back with two values. The wizard has to survive the user leaving, be unambiguous about what to copy where, and be honest that this friction is Spotify's rule, not ours.

Jobs — the waiting problem

MusicBrainz allows one request per second, so a cold 45-track sync exceeds a minute. The user must be able to walk away, know what is happening, and get the truth about what failed — not a spinner and a shrug.

Connect 01

Choosing a path, honestly

The first screen must do something most onboarding avoids: say plainly that you do not need this at all. Waxgrove is required to be fully useful with zero connectors (N6), so the wizard opens by making the free path visible rather than burying it.

The design decisions that matter here

Name the awkwardness and whose fault it is; show the free path before the paid friction; make the external step literal and resumable; surface quota immediately; and pre-empt the two real failure modes rather than letting them become support questions.

Jobs 01

Jobs 01 · Running
The rail chip is the persistent handle — the job is reachable from anywhere and never traps the user on this screen.
The unification worth noticing

The running job and the export-result view are the same surface in two states. Progress becomes outcome; the live rows become the per-track result rows demanded by F15. Building them as one screen removes a whole second design and matches how the data actually behaves.

Jobs 02

Jobs 03 · Sync state (F21)
“Synced” is not a boolean. Per service, per storefront, with revision drift counted — and divergence surfaced as a choice, never silently clobbered (D10).
The rule both surfaces share

Never let the system's difficulty become the user's confusion. Spotify's quota rules, Apple's regional catalogues and MusicBrainz's rate limit are all real constraints the user did not choose. The interface names them, attributes them, and says what can be done — the same instinct as §3.2's “never silently mismatch”, applied to infrastructure rather than to matching.
